# Приём заявок и фото: Cloudflare Workers → Telegram

Интерфейс остаётся на GitHub Pages. Worker принимает `POST /api/orders` (multipart/form-data), проверяет подпись Telegram, сохраняет заявку в D1 и отправляет текст и до 5 фото в заданный чат. Токен находится только в секретах Worker. Самостоятельного постоянного хранилища снимков нет: после загрузки Telegram сохраняются его `file_id`.

## Текущее подключение

Worker опубликован: `https://vashgruz-api.vashgruz-api.workers.dev`.
База D1 создана, миграция применена. Для проекта используется отдельный профиль Wrangler `vashgruz`, активированный в каталоге `backend/`. Входы других проектов не меняются.

Для подключения тестового `@vash_gruz_test_bot` запустите из корня проекта в обычном терминале:

```sh
./connect-telegram.command
```

Помощник скрыто запросит токен, проверит бота и новый аккаунт Cloudflare, найдёт группы в обновлениях Telegram и после выбора получателя сохранит `BOT_TOKEN` и `TELEGRAM_CHAT_ID` через stdin Wrangler. Токен не выводится и не сохраняется в файл. Если у бота есть webhook, помощник не меняет его и запросит ID группы вручную. Настройка не отправляет сообщений в группу.

Бот и группа подключены через секреты Cloudflare. URL Worker указан в `api-config.js`; опубликованный интерфейс отправляет реальные заявки при запуске через Telegram. Для локального просмотра без подписанных данных Telegram отправка недоступна.

## Что создать

1. Аккаунт Cloudflare. Если на компьютере уже был вход в другой аккаунт, явно выбрать новый аккаунт при `wrangler login` и проверить `wrangler whoami` перед созданием ресурсов.
2. Бот через официальный `@BotFather`, команда `/newbot`. В настройках Mini App указать `https://websitepreview26.github.io/vashgruz/`. Запускать из кнопки меню/профиля, чтобы Telegram передавал подписанные `initData` с пользователем.
3. Закрытая группа для заказов. Добавить бота и разрешить ему отправку сообщений, фото и альбомов. Для личного чата получатель должен сначала нажать Start у бота.

## Развёртывание

Нужен Node.js 24+. Команды выполнять из `backend/`:

```sh
npm install
npx wrangler login
npx wrangler whoami
npx wrangler d1 create vashgruz-orders
```

Подставить полученный `database_id` в `wrangler.jsonc`. При нескольких аккаунтах добавить в конфигурацию `account_id` нужного аккаунта.

```sh
npm run migrate
npx wrangler secret put BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
npm run deploy
```

Значения вводятся в скрытом запросе CLI. **Не вставлять токен в index.html, api-config.js, команды, коммиты или переписку.** ID группы можно посмотреть в обновлении `message.chat.id` через Telegram API `getUpdates` (только если у бота не установлен webhook). При существующем обработчике не сбрасывать его webhook ради получения ID; прочитать ID через этот обработчик.

После публикации проверить `https://<имя-worker>.<поддомен>.workers.dev/health`: `configured` должен быть `true`. В корневом `api-config.js` указать этот URL в `apiBase` (без `/api/orders`), затем опубликовать интерфейс. Без URL приложение остаётся в демо-режиме и никуда не отправляет данные.

## Проверка с телефона

В собственном тестовом боте и группе отправить заявку без фото, с одним фото и с несколькими. Проверить: альбом приходит ответом на текст заявки; повторное нажатие не создаёт вторую заявку; успех отображается после получения ответа API. Загрузка с `file://` предназначена только для локального демо — реальная отправка разрешена с указанного GitHub Pages origin и с проверенными initData.

## Оценка → предложение → решение клиента

Новая заявка — запрос оценки, а не подтверждённый заказ. Актуальные этапы: `received` → `processing` → `quoted` → `accepted`. Клиент может вместо согласия выбрать `discussion`, после чего менеджер публикует уточнённое предложение. `cancelled` закрывает оценку. Старые `confirmed`/`completed` остаются только в архивных данных; новые кнопки их не выставляют.

В группе администратор нажимает «Взять на оценку», затем «Назвать цену». Бот адресно запрашивает ответ: первая строка — сумма в BYN (например `150` или `150,50`), следующие строки — что включено и условия (до 600 символов). Цена хранится целым числом копеек. Ответ принимается только на зарегистрированный запрос цены, от администратора группы и для актуальной версии заявки. Изменить цену можно до принятия клиентом.

Клиент видит сумму и условия в приложении. «Подходит, согласовать» принимает стоимость, но не означает выполнение работ или бронирование времени. «Уточнить условия» позволяет отправить необязательный вопрос; менеджеру приходит уведомление, и заявка остаётся в работе. После принятия стоимости менеджер согласовывает время и детали. Бот пытается отправить клиенту личное уведомление о готовой цене со ссылкой в приложение. Если оно недоступно, предложение всё равно сохранено, а группа получает предупреждение.

`POST /api/orders/list` с JSON `{initData}` возвращает до 100 доставленных заявок только текущего Telegram-пользователя, сначала активные, затем архивные; удалённые из личного списка исключаются. `POST /api/orders/decision` принимает `{initData,id,version,action,actionId,note}`, где action — `accept` или `discuss`; действие проверяется по владельцу и версии предложения. Изменение цены и согласие клиента защищены от гонок, дубликатов и принятия старой цены. В интерфейсе список обновляется каждые 10 секунд, пока открыт; ввод вопроса не перерисовывается во время набора.

Управление работает через защищённый `/telegram/webhook`. Проверяются секрет webhook, группа, ID сообщения, администратор и версия кнопки. Бот должен иметь возможность проверять администраторов через `getChatMember`.

После миграций и публикации Worker запустить `python3 backend/tools/enable_statuses.py` из корня проекта. Скрипт генерирует секреты для webhook и настройки, передаёт их в Cloudflare через stdin и обновляет кнопки старых сообщений. Токен бота не считывается. Чужой webhook не заменяется. `MINI_APP_URL` задаёт адрес приложения для кнопки web_app в личном уведомлении; параметр order открывает нужную оценку после проверки владельца. `BOT_USERNAME` используется для запасной ссылки startapp. При смене бота обновить BOT_USERNAME и секрет BOT_TOKEN.

## Контакт Telegram и адреса

Имя берётся из проверенных Telegram initData. `requestContact` в мини-аппе открывает системный запрос согласия, но сам номер передаётся боту отдельным `message.contact`. Webhook принимает сообщения и callback_query; контакт сохраняется только из личного чата, если `contact.user_id`, отправитель и ID чата совпадают. `POST /api/contact` с `{initData}` возвращает номер только его владельцу. Миграция `0003_contacts.sql` добавляет контакты и переносит номер из последней успешно отправленной заявки. Подтверждённый номер и вручную введённый номер после успешного заказа подставляются в следующих заказах. При отказе или задержке Telegram доступен ручной ввод без автоматического открытия клавиатуры.

Адреса погрузки и выгрузки показаны рядом, перед настройками этажей. Для переезда переход к контакту отключён, пока не заполнены оба адреса; для других услуг достаточно одного.

## Управление списком

Вкладки «Активные / Архив», по 8 карточек с кнопкой «Показать ещё». Действия находятся в меню «⋯» карточки и деталей: повторить оценку, архивировать, восстановить, отменить текущую оценку или удалить из личного списка. Локальные черновики управляются без запроса API.

`POST /api/orders/organize` принимает `{initData,id,action,version}`. `archive`, `restore`, `delete` меняют только `customer_visibility`, не бизнес-статус. Удаление из списка — скрытие у клиента, а не уничтожение записи у менеджера. Архив и удаление синхронизируются между устройствами и не отменяют оценку. В течение 6 секунд последнюю операцию можно отменить кнопкой в уведомлении. Отдельное действие `cancel` проверяет версию, переводит оценку в cancelled, архивирует её и уведомляет менеджера; повтор не дублирует уведомление. Даже последующее изменение статуса менеджером не возвращает удалённую из списка запись. Миграция `0005_order_organization.sql` создаёт поле видимости и отправляет старые закрытые заявки в архив.

## Повторные попытки и ограничения

- Фото уменьшаются в приложении до длинной стороны 1600 px и JPEG; максимум 2 МБ на фото, 5 фото, 12 МБ на весь HTTP-запрос. Оригиналы на backend не сохраняются.
- D1 хранит текст заявки, контакты, ID Telegram-пользователя, статус и Telegram file_id. Перед реальным запуском определить срок хранения и актуализировать политику обработки данных заказчика.
- Черновики формы сохраняются в браузере; сами фото остаются только до перезагрузки приложения. При возобновлении черновика после перезагрузки их нужно выбрать заново.
- При явном отказе Telegram повтор безопасен: отправляется только недоставленная часть. При потере ответа Telegram невозможно гарантировать, что сообщение не было доставлено. Такие заявки переходят в `uncertain` (или остаются `sending_*`, если Worker прерван) и требуют проверки группы; автоматический повтор блокируется. Это сознательная защита от дубликатов, а не обещание exactly-once.
- В интерфейсе показывается лишь подтверждённая доставка. «Отправлена» не означает, что менеджер уже прочитал заявку.
- Лимит: 10 новых заявок на одного проверенного Telegram-пользователя за час. API не принимает произвольные chat_id от клиента. Не включать логирование тела запросов и токенов.

## Перенос

Контракт интерфейса — multipart POST с `initData`, `requestId`, JSON-полем `order` и повторяющимся полем `photos`. В ответе успеха: `{ok:true,id,photoCount}`. Для другого хостинга сохраняем этот контракт и проверку Telegram, заменяем D1-адаптер обычной SQL-базой и меняем только `apiBase`. Внешний вид приложения переделывать не нужно.
